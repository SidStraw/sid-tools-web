## XML adapter contract

- Browser-only `sitemap-xml.ts` imports the built public `@sid-tools/core/sitemap` API. The controller loads adapter/core only on Run. The normalized core is unchanged by this integration.
- Input is paste-only decoded text, not a file/network reader. UTF-8 size is measured from **current textarea content**; browsers may normalize line endings, so it is not an original on-disk file-size claim. Text over 2,000,000 code units is necessarily over the local byte cap and rejected before encoder/source-index/XML allocation; its byte count stays null.
- Before DOMParser: conservative case-insensitive DOCTYPE/entity declaration-like rejection (including inside comments/CDATA), XML 1.0/UTF-8 declaration policy, byte limit, bounded lexical element/depth scan. No DTD/entity expansion, XSLT, XInclude, remote links or external XML library. Built-in references are decoded only by inert XML parsing after the safety gate.
- Locator scan handles quoted `>`, comments, CDATA, processing instructions and self-closing tags. After DOMParser, all lexical opening names must agree with DOM preorder. Both Chromium XHTML and Mozilla parsererror namespaces are rejected before source mapping; browser error prose is never rendered/exported. Malformed XML is located at document scope, not a fabricated precise error line. The two browser parsererror namespaces are reserved/rejected conservatively if supplied in input too.
- Exact Sitemap 0.9 root/entry/field namespaces and direct-child cardinality; prefixed equivalent namespaces work. Every direct local-name `url`/`sitemap` entry in the relevant root retains its original ordinal/pointer, even a wrong-namespace entry. Such an entry is not certified: fields remain absent and diagnostics identify its source. Other unsupported root children retain source-located issues, not fabricated valid URL entries. Nested wrappers never masquerade as direct entries.
- Each recognized direct field is inspected. Duplicates retain first value and all occurrence positions, with explicit duplicate error/incomplete status. Unknown/foreign tags, attributes except namespace declarations, mixed text, PI and nested element content remain source-located unsupported diagnostics. Extensions (image/video/news/hreflang, etc.) are not silently treated as valid.
- The exported top-level `valid`/`complete` refer to full XML adapter + core checks. Nested `report` is the unchanged normalized-core result and may have valid supported fields despite unsupported XML. Neither level claims live HTTP or indexing verification. Source map contains offsets/line/column/pointers, not copies of raw XML.

## Honest limits and semantics

- Protocol: 50,000 entries / 52,428,800 uncompressed bytes. Local: 10,000 entries / 2,000,000 UTF-8 bytes / 100,000 XML elements / 128 levels. Normalized pointer+field budget 2,000,000 UTF-16 code units; field 4,096; loc 2,047. Exceeding a core preflight limit retains source count but does not return partial checked entries.
- Sitemap 0.9 only. No gzip, file upload, URL download, crawling, robots/canonical/status/ownership or search-console integration. Not an XSD validator. All explicit supported format/calendar/path rules are in static page help, readable without JS.
- Exact trimmed loc string determines duplicates (no canonical equivalence). WHATWG URL host including nondefault port determines mixed-host; scheme is not host. Tree uses parsed origin/pathname and preserves query variants/duplicates as separate original entries. Invalid loc entries stay in list but not tree. Date validity is not evidence of actual content freshness.
- Native disclosure lists avoid pretending to implement an ARIA tree widget; keyboard users can expand/collapse and activate branch filters normally. Tree is a focusable internally scrolling complementary region. Max 12 visual segments; remaining path merged as one node, full pathname and original list retained. Batches of 60 siblings, lazy child expansion, 50 entries/diagnostics per page. Filters are local-only and never enter URL/storage.
- Input edits/rechecks/demo changes/clear/dispose invalidate report, source maps, all filters and source labels; render/list/diagnostic-page listeners are aborted. Lazy revision tokens guard cleared/edited/disposed state; no original input snapshot is retained across import. Blob URLs are revoked on edit/recheck/clear/dispose and before re-export. Explicit JSON download may contain sensitive URLs/query strings; no automatic sanitization or safe-to-share promise.
